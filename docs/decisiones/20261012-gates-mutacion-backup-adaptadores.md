# Decisión: gates de mutación y ejecución de backups en adaptadores

- **Fecha:** 2026-10-12
- **Estado:** vigente
- **Objetivo:** reducir el riesgo de que un adaptador controlado ejecute una mutación sin haber recibido la respuesta explícita de acción y la decisión sí/no de backup.
- **Necesidad:** el coordinador y las instrucciones MCP pedían ambas respuestas, pero `execute_sql_file`, `execute_change_bundle` y `deploy_apex_page` aceptaban llamadas sin campos que las representaran. El bundle también aceptaba `snapshot.sql` en el manifiesto sin ejecutarlo.
- **Decisión:** todas las herramientas mutativas MCP exigen `confirmed=true` y `backup_choice=yes/no`; fallan cerradas cuando falta una decisión. Para SQL directo, `backup_choice=yes` requiere un SQL de backup dedicado, ejecutado antes del cambio. Para bundles, `yes` requiere `snapshot.sql`, ejecutado después del preflight y antes de apply. Para importación APEX, `yes` requiere un export nativo previo en una ruta distinta; el adaptador verifica la estructura básica y registra su hash, pero no puede comprobar que corresponda al estado vivo exacto. Si el backup falta o falla, no se ejecuta la mutación. `backup_choice=no` no admite artefacto de backup.
- **Alternativas:** dejar la confirmación solo en prompts; descartado porque la herramienta no distingue omisiones de una llamada directa. Inferir/crear backups automáticamente para SQL arbitrario; descartado porque el adaptador no puede determinar con seguridad el alcance de cualquier DML/DDL. No hacer rollback automático tras el apply; mantenido porque Oracle DDL puede confirmar implícitamente y el bundle no demuestra que `rollback.sql` sea seguro ni reversible.
- **Límite de confianza:** los argumentos obligatorios bloquean omisiones accidentales, pero no son un token de aprobación autenticado; un cliente puede fabricar `confirmed=true`. La autenticidad de la interacción sigue dependiendo del canal/agente que recibe la respuesta humana.
- **Impacto y dependencias:** cambia el contrato de herramientas MCP y los argumentos de `Execute-OracleSql.ps1`, `Deploy-ApexPage.ps1` e `Invoke-OracleApexChange.ps1`. Se alinean las skills de coordinación, workspace, schema, page automation, delivery y governance, el routing, manuales, catálogos pertinentes, ejemplos, pruebas y changelog. El backup afirmativo añade ejecución antes del cambio; la respuesta negativa conserva el camino sin backup.
- **Riesgos:** un backup SQL puede ser incorrecto aunque termine con éxito; quien prepare el artefacto debe verificar que cubra exactamente el alcance. El export APEX previo se valida sintácticamente, no contra el estado actual vivo. Los clientes MCP que llamaban herramientas mutativas sin estos argumentos deben actualizarse. Las rutas externas al repositorio no quedan forzadas técnicamente por esta implementación.
- **Compatibilidad:** no cambia Oracle ni APEX. Conserva lectura inmediata mediante `execute_readonly_query` o `Execute-OracleSql.ps1 -ReadOnly`; las lecturas no piden confirmación. Los canales APEX externos mantienen sus propias instrucciones y limitaciones.
- **Validación:** pruebas unitarias cubren decisiones faltantes, ejecución backup→mutación, detención ante fallo, requerimiento de snapshot y registro de la elección. Se ejecutarán pruebas PowerShell/estáticas aplicables, auditoría de enlaces, CI y auditoría independiente de solo lectura.
- **Reversión de esta decisión:** revertir en conjunto los gates de adaptadores, los scripts PowerShell, sus pruebas, instrucciones/documentación sincronizada y changelog. No requiere cambiar ni revertir datos Oracle/APEX.
- **Descontinuación:** si se adopta posteriormente un mecanismo de aprobación autenticado, se puede reemplazar el booleano/choice del cliente manteniendo el principio de fail-closed.
- **Aclaración posterior (2026-10-12):** `rollback.sql` no es un artefacto requerido en bundles. Si se declara, se valida como archivo local del bundle; el adaptador no lo ejecuta ni garantiza que sea seguro o reversible.
- **Aclaración posterior (2026-10-12):** si `backup_choice=no`, el bundle no puede declarar `snapshot` en `change.json`; los adaptadores MCP y PowerShell detienen la ejecución antes del preflight.
