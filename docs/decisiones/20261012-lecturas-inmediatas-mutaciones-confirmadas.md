# Decisión: lecturas inmediatas y mutaciones confirmadas

- **Fecha:** 2026-10-12
- **Estado:** vigente
- **Objetivo y necesidad:** reducir pasos innecesarios al revisar objetos Oracle/APEX y evitar backups, conteos previos y paquetes administrativos que el usuario no pidió. El usuario reportó que una solicitud de borrado tardó aproximadamente 20 minutos, mientras que el trabajo manual esperado era menor a un minuto, excluyendo la ejecución Oracle.
- **Alcance:** instrucciones globales de Oracle/APEX, diagnósticos, cambios puntuales de datos/schema/APEX, routing, plantillas, adaptadores y pruebas del repositorio `apex.skills`.
- **Decisión:**
  1. Una solicitud de revisar, consultar o mostrar datos/especificaciones se interpreta como solo lectura. Verificar la identidad/destino una vez si no se ha comprobado en la conexión activa y consultar inmediatamente. No ejecutar inventarios, QA, escaneos de privilegios, diagnósticos de workspace ni flujos de cambio como preflight rutinario.
  2. Antes de cualquier mutación, pedir una sola confirmación que identifique ambiente, objeto y operación, confirme si procede y solicite una respuesta explícita sí/no para backup. No ejecutar si falta cualquiera de esas dos respuestas; preguntar solo la decisión omitida y esperar. El silencio no significa que se rechazó el backup. La respuesta completa es la única confirmación; no agregar aprobaciones sucesivas.
  3. No crear backup, snapshot ni artefacto de respaldo si el usuario no lo pidió o lo rechazó. Si acepta, crear solo un respaldo adecuado al alcance solicitado y retenerlo hasta que pida retirarlo.
  4. No exigir conteo de filas antes de INSERT, UPDATE, DELETE, MERGE u otra transacción. Hacer conteos si el usuario los solicita o si una ambigüedad concreta impide determinar el alcance.
  5. Ejecutar DML puntual por la ruta directa disponible, conservar el evento de auditoría normal y verificar el resultado solicitado. Reservar `change.json`, preflight de fingerprint y documentación formal para cambios donde protejan materialmente una corrección existente, migración o cambio coordinado.
  6. No explicar rollback rutinariamente; hacerlo solo si se solicita o una limitación concreta lo hace necesario.
  7. No inspeccionar grants como validación previa, intermedia o final de una operación solicitada. Ejecutarla con la credencial configurada y reportar la respuesta real de Oracle/APEX, incluidos errores de privilegios. Consultar grants solo a solicitud explícita o para diagnosticar un error de acceso observado.
- **Alternativas consideradas:** mantener el flujo formal con paquete/snapshot para todo cambio; exigir un conteo para limitar operaciones; o eliminar toda confirmación. Se descartan: el primero y el segundo agregan costos que el usuario no pidió; el tercero contradice la solicitud explícita de confirmar el cambio y la opción de backup.
- **Impacto, riesgos y dependencias:** menos consultas y artefactos en solicitudes simples. Si el usuario rechaza backup, la recuperación puede no estar disponible para una acción no reversible; la confirmación debe especificar la operación exacta y el ambiente. La cuenta Oracle/APEX seleccionada y los permisos efectivos no cambian. No se cambian runtime, conectores, credenciales ni objetos de base de datos.
- **Compatibilidad:** aplica al coordinador Oracle/APEX y adaptadores Claude/OpenAI; conserva las rutas SQLcl/MCP existentes. APEX continúa usando export/import nativo y herramientas autorizadas. No altera versión Oracle/APEX.
- **Validación:** regresiones para lecturas inmediatas, una confirmación, elección de backup, ausencia de conteo previo y uso de bundle solo cuando corresponde; pruebas focalizadas por hito y luego suite/CI/auditorías aplicables. La latencia real de Oracle se separará de preparación local, conexiones y fases del bundle; no se afirmará reducción temporal sin mediciones.
- **Rollback de la implementación:** revertir conjuntamente las reglas, matrices, adaptadores, templates, pruebas y esta decisión desde el diff de Git. No requiere cambios ni rollback en Oracle/APEX.
- **Descontinuación:** ninguna skill o ruta nueva se agrega. Las instrucciones de bundle permanecen para correcciones/migraciones justificadas.
