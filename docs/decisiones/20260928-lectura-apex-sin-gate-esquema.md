# Decisión: lectura de metadata APEX sin gate por esquema SQLcl

- **Fecha:** 2026-09-28
- **Estado:** vigente
- **Necesidad:** recuperar la inspección de páginas APEX en producción cuando la credencial Oracle conectada tiene grants de lectura, pero su usuario no es el parsing schema asignado al workspace.
- **Evidencia:** el MCP controlado devuelve aplicación, workspace, owner, esquemas asignados e identidad Oracle, pero devolvía `APEX_CONTEXT_INVALID` únicamente porque `SESSION_USER` no aparecía en los esquemas del workspace. En producción se observó `DDELACRUZ` en `ZAI`, workspace `DE`, owner `DATA`; una ruta APEX con la misma identidad sí pudo consultar `APEX_APPLICATION_PAGE_REGIONS`. El helper `apex_get_page_details` de esa ruta falló por `ORA-00904: REGION_TEMPLATE`, mientras que la vista pública consultada directamente funcionó.
- **Decisión:** la asociación de `SESSION_USER` con parsing schemas se reporta como dato, no como autorización ni gate. Para inspección, verificar identidad y destino reales; luego usar helpers APEX compatibles o consultar las vistas públicas `APEX_APPLICATION_*` con binds. Si un helper falla por incompatibilidad de columnas, continuar por la vista pública y registrar el error del helper.
- **Alternativas consideradas:** exigir que el usuario SQLcl sea el parsing schema; usar tablas internas `WWV_FLOW_*`; parar al fallar `apex_get_page_details`; usar la ruta APEX verificada y vistas públicas. Se elige la última: no restringe grants Oracle, evita tablas internas y conserva evidencia del destino.
- **Impacto y dependencias:** modifica `inspect_apex_context` para devolver `session_schema_associated` sin bloquear; actualiza el skill coordinador, diagnóstico y documentación de herramientas. No agrega dependencias ni cambia perfiles, usuarios, grants, objetos de producción o `.env.example`.
- **Riesgo:** una consulta a vistas APEX puede no estar concedida o una vista puede cambiar entre versiones. En ese caso se informa la respuesta real del servicio y se prueba otra ruta del mismo ambiente; no se interpreta el desajuste de esquema como denegación.
- **Compatibilidad:** SQLcl y MCP APEX configurados por el usuario; usar las vistas públicas disponibles en la versión observada. Bindear IDs de aplicación/página.
- **Validación:** producción respondió `ENVIRONMENT_READY`; identidad `DDELACRUZ`, base/contenedor `ZAI`, workspace `DE`. `apex_get_page_details` falló por columna `REGION_TEMPLATE`; lectura directa de `APEX_APPLICATION_PAGE_REGIONS` con binds funcionó para app 130/página 610. No se modificó base ni aplicación. No se ejecutó la suite local de pruebas.
- **Reversión:** revertir el retorno informativo `session_schema_associated` en `inspect_apex_context` y las instrucciones de fallback en skills/docs; no requiere rollback de base de datos.
