# Decisión: lecturas Oracle/APEX directas y vigencia de errores históricos

- **Fecha:** 2026-09-29
- **Estado:** vigente
- **Objetivo:** reducir la latencia antes de inspeccionar un objeto específico y evitar que una sesión previa determine el acceso de la sesión actual.
- **Evidencia:** el flujo documental acumulaba comprobaciones de sesión, privilegios, inventario de entorno y contexto APEX antes de consultar algunos objetos. Los reportes recientes también repitieron errores anteriores de runtime/contexto como limitaciones vigentes sin demostrar el estado de la ruta actual. La consulta al servicio remoto puede tener latencia propia; este cambio elimina rondas seriales que no aportan a una lectura simple.
- **Decisión:** para lecturas puntuales, verificar identidad/destino una vez por conexión activa y consultar enseguida. Reutilizar evidencia viva; si aún no existe, hacer una sonda mínima antes de leer contenido. Ejecutar inventario, privilegios o diagnóstico de workspace solo cuando una ambigüedad o error actual lo justifique. No usar ni presentar resultados cuando el destino observado no coincide. La memoria es contexto y pista de consulta, no autoridad de acceso: revalidar errores variables en la ruta y credencial actuales, probar otra ruta configurada del mismo ambiente si falla, y considerar el trabajo bloqueado solo después de fallos actuales de las rutas disponibles.
- **Alternativas consideradas:** mantener el conjunto de sondas antes de cada solicitud; eliminar toda comprobación de identidad; ignorar por completo la memoria; repetir siempre los intentos fallidos históricos. Se conserva una verificación de destino y el contexto útil, sin multiplicar rondas ni convertir un resultado antiguo en un veto.
- **Impacto y dependencias:** actualiza `skills/apex`, `skills/apex-database-diagnostics`, documentación de rutas, changelog y una prueba de regresión de las reglas. No cambia credenciales, grants, permisos por ambiente, conectores, runtime ni objetos Oracle/APEX. No requiere cambios de routing porque continúa usando la skill diagnóstica existente.
- **Riesgos y compatibilidad:** una conexión nueva o un cambio de ambiente requiere volver a verificar el destino. La latencia intrínseca del servidor remoto persiste; no se ha afirmado una mejora de tiempo medida. La consulta efectiva sigue decidiendo si el objeto es accesible.
- **Validación:** ejecutar prueba focalizada, auditoría integral, suite completa, CI local y revisión independiente antes de integrar/publicar.
- **Reversión:** revertir los textos, prueba y esta decisión; no requiere rollback de configuración ni base de datos.
